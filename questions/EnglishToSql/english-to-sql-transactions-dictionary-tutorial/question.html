English-to-SQL tutorial

In this tutorial, you will describe a data analysis plan in using canonical English. The english to code PrairieLearn element will turn your plan into SQL that you can review, edit, preview, and submit.

DATA 100 reference sheet: Open the reference sheet in a new tab and keep it available throughout the assessment.

How to use the English-to-SQL tool

  1. Read the dataset description and question below.
  2. Write the operations needed to answer the question in the English analysis-plan box.
  3. Click Generate SQL. The tool generates SQL from your plan and displays a result preview.
  4. Review the generated SQL and preview. You may edit the SQL directly if you want to.
  5. Click Save & Grade when you are ready. This grades the SQL currently visible in the editor.
Important: Clicking Generate SQL again regenerates the SQL from your English plan and replaces any SQL edits. Clicking Save & Grade preserves your edits and does not regenerate the SQL.

Practice question: transactions analysis plan

Consider a transactions dataset with the following columns:

ColumnDescription
transaction_ida unique identifier for each transaction
customer_idan identifier for the customer associated with the transaction
store_idan identifier for the store where the transaction occurred
datethe date of the transaction
yearthe year of the transaction
totalthe total dollar amount of the transaction

Each row of the dataset represents one transaction.

Note: Customers can make more than one transaction at more than one store on a particular day.

Write an analysis plan for the question below.

  • Your analysis plan should start with the dataset above and result in a table that answers the question.
  • Your final table must only include rows that are relevant to the question. No extra rows.

Describe every operation clearly in English. Phrases such as the following are supported:

  • select or select distinct
  • filter rows where or filter for
  • group rows by or for each unique
  • join with both table names and matching columns for a multi-table question
  • compute count of, compute count distinct of, compute sum of, compute average of, compute minimum of, or compute maximum of; sum their is also accepted for a sum
  • keep groups where or aggregate the result with
  • order by with ascending or descending
  • keep the first or skip the first

Name every table and column exactly as shown above. Include all comparison operators, values, calculation inputs, and sort directions needed by your steps. Code-like shorthand such as df[...], groupby, or more_than is not accepted as English analysis-plan wording.
